**الإصدار: 1.0.0**

## جرّب الديمو (أمر واحد)

> GitHub نفسه لا يشغّل باك إند، فلا يوجد "رابط ديمو حي" مباشر من الريبو.
> الديمو يعمل عبر Docker Compose: أمر واحد يشغّل Postgres + الخادم +
> الواجهة معاً — محلياً، أو في السحابة عبر GitHub Codespaces.

### محلياً (Docker)

المتطلب الوحيد: Docker و Docker Compose مثبّتان على جهازك. من جذر المشروع:

```bash
docker compose up --build
```

ثم افتح http://localhost:5173

**بيانات الدخول التجريبية للديمو:**

- كود الشركة: `COMP001`
- اسم المستخدم: `admin`
- كلمة المرور: `admin123`

> ⚠️ هذه قيم ديمو معلنة فقط (موجودة في `docker-compose.yml`)، ويجب تغييرها
> فوراً في أي استخدام حقيقي. لتجاوزها، أنشئ ملف `.env` في جذر المشروع قبل
> التشغيل (لن يُرفع إلى git أبداً):
>
> ```env
> POSTGRES_PASSWORD=<كلمة مرور قاعدة البيانات>
> JWT_SECRET=<قيمة عشوائية طويلة>
> SEED_ADMIN_PASSWORD=<كلمة مرور قوية للمدير>
> ```
>
> لإيقاف الديمو: `docker compose down` (تبقى البيانات في الـ volume؛
> لحذفها أيضاً أضف `-v`).

### في السحابة (GitHub Codespaces — بدون تثبيت أي شيء)

1. افتح الريبو على GitHub، ثم **Code → Codespaces → Create codespace on branch `refactor/full`**.
2. انتظر حتى يكتمل إنشاء البيئة — يقوم Codespaces تلقائياً بتشغيل
   `docker-compose.yml` كاملاً (قاعدة البيانات، ثم الخادم، ثم الواجهة).
3. افتح المنفذ **5173** من تبويب Ports، وسجّل الدخول بنفس بيانات الديمو أعلاه.

التفاصيل في `.devcontainer/README.md`.

## نظرة عامة على النظام

نظام إدارة الشاحنات هو تطبيق ويب متكامل مصمم لإدارة أسطول الشاحنات بكفاءة عالية. يوفر النظام واجهة سهلة الاستخدام للمديرين والسائقين لتتبع وإدارة جميع العمليات المتعلقة بالشاحنات.

### المميزات الرئيسية
- **نظام متعدد الشركات**: كل شركة لها بياناتها المنفصلة والمؤمنة
- **إدارة الشاحنات**: تسجيل وإدارة معلومات الشاحنات
- **إدارة الرحلات**: تتبع الرحلات وحالتها
- **إدارة المصاريف**: تسجيل وتتبع جميع المصاريف
- **إدارة الصيانة**: جدولة وتتبع عمليات الصيانة
- **التقارير**: تقارير شاملة ومفصلة
- **نظام المستخدمين**: إدارة صلاحيات المديرين والسائقين
- **الأمان المتقدم**: حماية كاملة لبيانات كل شركة

## التقنيات المستخدمة

- **الواجهة الأمامية**: React 18 + TypeScript + Vite + Tailwind CSS
- **الخادم**: Node.js + Express
- **قاعدة البيانات**: PostgreSQL — قاعدة بيانات باسم `truck_system`، وتتكون من 6 جداول
- **المصادقة**: JWT مع تشفير كلمات المرور باستخدام bcrypt
- **الرسوم البيانية**: Recharts
- **تصدير التقارير**: Excel عبر مكتبة xlsx

## المتطلبات الأساسية

- Node.js (الإصدار 16 أو أحدث) مع npm
- PostgreSQL (مثبّت محلياً أو خدمة سحابية) مع قاعدة بيانات باسم `truck_system`
- متصفح ويب حديث

## التشغيل

### الخطوة 1: إنشاء قاعدة البيانات

أنشئ قاعدة بيانات PostgreSQL باسم `truck_system`، مثلاً:

```bash
createdb truck_system
```

أو من داخل `psql`:

```sql
CREATE DATABASE truck_system;
```

### الخطوة 2: إعداد متغيرات بيئة الخادم

```bash
cd server
cp .env.example .env
```

ثم عدّل القيم في `server/.env` بما يناسب بيئتك (راجع قسم "متغيرات البيئة" أدناه).

### الخطوة 3: تثبيت اعتماديات الخادم وتجهيز الجداول

```bash
cd server
npm install
npm run init-db
```

يقوم `npm run init-db` بإنشاء الجداول الستة في قاعدة البيانات، وينشئ شركة تجريبية وحساب مدير افتراضي للتطوير.

### الخطوة 4: تشغيل الخادم

```bash
cd server
npm start
```

يعمل الخادم على المنفذ 3001: http://localhost:3001

### الخطوة 5: تشغيل الواجهة الأمامية (في نافذة طرفية جديدة)

```bash
cp .env.example .env
npm install
npm run dev
```

تعمل الواجهة على المنفذ 5173: http://localhost:5173

> ملاحظة: الواجهة توجّه طلبات `/api` إلى الخادم على المنفذ 3001 عبر إعدادات الوكيل (proxy) في `vite.config.ts`.

## متغيرات البيئة

### الخادم (`server/.env`)

```env
PORT=3001
NODE_ENV=development
JWT_SECRET=<مفتاح قوي وعشوائي وطويل>
DATABASE_URL=postgres://USER:PASSWORD@localhost:5432/truck_system
```

- `DATABASE_URL`: سلسلة اتصال PostgreSQL. يمكن استخدام `SUPABASE_URL` بدلاً منها عند استخدام استضافة سحابية متوافقة.
- `JWT_SECRET`: مفتاح توقيع التوكنات — استخدم قيمة قوية وعشوائية ولا تشاركها.
- لا تضع أي كلمة مرور أو سر حقيقي في التوثيق أو في git؛ ملف `.env` مستثنى من التتبع عبر `.gitignore`.

### الواجهة الأمامية (`.env` في الجذر)

```env
VITE_API_BASE_URL=/api
```

القيمة الافتراضية `/api` تعمل مع إعداد الوكيل في `vite.config.ts` أثناء التطوير. راجع `.env.example` في الجذر.

## دليل الاستخدام

### تسجيل شركة جديدة
1. انتقل إلى صفحة "تسجيل شركة جديدة" (`/register-company`)
2. املأ بيانات الشركة:
   - **اسم الشركة**: اسم الشركة
   - **كود الشركة**: كود فريد للشركة (مثال: COMP001)
   - **البريد الإلكتروني**: بريد الشركة
   - **رقم الهاتف**: هاتف الشركة
   - **العنوان**: عنوان الشركة
3. املأ بيانات المدير:
   - **اسم المدير**: اسم مدير الشركة
   - **اسم المستخدم**: اسم المستخدم للمدير
   - **كلمة المرور**: كلمة المرور
   - **البريد الإلكتروني**: بريد المدير
4. اضغط "إنشاء الشركة"

> مسار `/register-company` عام عن قصد: هو الطريقة المخصصة لإنشاء شركة جديدة وحساب مدير لها. راجع هذا القرار قبل أي استخدام إنتاجي.

### تسجيل الدخول
1. افتح التطبيق في المتصفح
2. أدخل:
   - **كود الشركة**: كود الشركة المسجلة
   - **اسم المستخدم**: اسم المستخدم
   - **كلمة المرور**: كلمة المرور
3. اضغط "تسجيل الدخول"

### البيانات التجريبية (للتطوير فقط)
- **كود الشركة**: `COMP001`
- **اسم المستخدم**: `admin`
- **كلمة المرور**: تُعرض في الطرفية عند تشغيل `npm run init-db` فقط، ويجب تغييرها فوراً بعد أول تسجيل دخول.

هذه البيانات للتطوير المحلي فقط، ولا تُستخدم في أي بيئة مشتركة أو إنتاجية.

لوحة التحكم تعرض نظرة عامة على النظام:
- **إجمالي الشاحنات**: عدد جميع الشاحنات في الشركة
- **الرحلات النشطة**: عدد الشاحنات في رحلات حالياً
- **إجمالي المصاريف**: مجموع جميع المصاريف بالريال السعودي
- **الشاحنات في الصيانة**: عدد الشاحنات تحت الصيانة
- **الرحلات النشطة**: قائمة بالرحلات الجارية مع نسبة الإنجاز

- انتقل إلى صفحة "الشاحنات"
- ستجد قائمة بجميع شاحنات شركتك مع معلوماتها الأساسية
- يمكنك تصفية الشاحنات حسب الحالة (متاحة، في رحلة، صيانة)

#### إضافة شاحنة جديدة
1. اضغط على زر "إضافة شاحنة"
2. املأ المعلومات المطلوبة:
   - **رقم الشاحنة**: رقم تعريفي للشاحنة
   - **الموديل**: موديل الشاحنة
   - **سنة الصنع**: سنة تصنيع الشاحنة

3. اضغط على زر "تعديل"

## قاعدة البيانات

النظام يستخدم PostgreSQL. الجداول الستة (تُنشأ عبر `npm run init-db` من داخل `server/`):

- **companies**: الشركات
- **users**: المستخدمون (مرتبط بالشركة)
- **trucks**: الشاحنات (مرتبط بالشركة)
- **trips**: الرحلات (مرتبط بالشركة)
- **expenses**: المصاريف (مرتبط بالشركة)
- **maintenance_records**: سجلات الصيانة (مرتبط بالشركة)

## الأمان

### نظام متعدد الشركات
- كل شركة لها بياناتها المنفصلة تماماً
- لا يمكن لشركة الوصول لبيانات شركة أخرى
- جميع الطلبات تتحقق من انتماء المستخدم للشركة الصحيحة

### المصادقة
- يستخدم النظام JWT للمصادقة
- جميع الطلبات (عدا تسجيل الدخول وتسجيل شركة جديدة) تتطلب توكن صالح
- التوكن يحتوي على معلومات الشركة
- التوكن صالح لمدة 24 ساعة

### الصلاحيات
- المدير: صلاحيات كاملة على شركته فقط
- السائق: صلاحيات محدودة على شاحنته فقط

### حماية البيانات
- تشفير كلمات المرور باستخدام bcrypt
- Rate limiting للحماية من الهجمات
- CORS محدود للدومينات المسموحة
- التحقق من انتماء البيانات للشركة في كل طلب

## حالة المشروع

النظام يعمل كنسخة تجريبية (ديمو) للاستخدام المحلي. راجع `COMPLETION_SUMMARY.md` لمعرفة ما هو منفَّذ وما الذي لم يُختبر أو يحتاج مراجعة قبل أي استخدام إنتاجي — ومن ذلك: غياب الاختبارات الآلية، ووجود قيم افتراضية ثابتة في الكود يجب استبدالها بمتغيرات بيئة، وبيانات الدخول التجريبية التي يجب تغييرها فوراً.

## استكشاف الأخطاء

### مشاكل شائعة

#### مشكلة CORS
إذا واجهت مشكلة CORS:
1. تأكد من أن الخادم يعمل على المنفذ 3001
2. تأكد من إعدادات CORS في `server/server.js`
3. أعد تشغيل الخادم

#### مشكلة الاتصال بقاعدة البيانات
إذا واجهت مشكلة في الاتصال بقاعدة البيانات:
1. تأكد من أن PostgreSQL يعمل وأن قاعدة `truck_system` موجودة
2. تأكد من صحة `DATABASE_URL` (أو `SUPABASE_URL`) في `server/.env`
3. شغل `npm run init-db` من داخل `server/` لإنشاء الجداول
4. راجع سجلات الخادم في الطرفية لمعرفة رسالة الخطأ

#### مشكلة في الواجهة
إذا واجهت مشكلة في الواجهة:
1. تأكد من تثبيت جميع المتطلبات من الجذر: `npm install`
2. تأكد من أن الخادم يعمل على المنفذ 3001 (الواجهة توجّه طلبات `/api` إليه)
3. امسح cache المتصفح
4. أعد تشغيل خادم التطوير

### سجلات الأخطاء
- سجلات الخادم تظهر في الطرفية
- أخطاء الواجهة تظهر في console المتصفح
